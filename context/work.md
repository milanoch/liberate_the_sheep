## Чит «все уровни» в настройках (2026-10-29)

По запросу пользователя добавлен отдельный SheepToggle «ЧИТ: ВСЕ УРОВНИ» /
«CHEAT: ALL LEVELS». Он даёт доступ ко всему текущему каталогу39уровней
для ручной проверки. Выключение возвращает обычные замки по реальному
прогрессу. Само включение не отмечает будущие уровни пройденными; победы
во время включённого чита также не меняют основной прогресс и рекорды.
Бессмертие остаётся отдельной настройкой: чит доступа не защищает от бомб
или потери сердец.

SettingsData содержит cheatModeEnabled=false, SettingsStore — getter/setter.
SettingsFormat v3 добавляет четвёртое значение после immortal. Файлы v1/v2
читаются с cheat=false и сохраняют прежний язык/музыку/бессмертие. Файлы
SaveData вручную не править. Флаг сохраняется через обычный callback меню.
SettingsView получил ещё одну строку с тем же переключателем-овечкой;
существующая прокрутка позволяет добраться до всех настроек.

LevelSelectView получает allLevelsUnlocked отдельно от highestUnlocked,
поэтому открывает все кнопки, сохраняя реальные галочки прохождения.
MenuController разрешает переход на любой валидный номер при cheat=true;
LevelController при старте учитывает тот же флаг и не перенаправляет на
обычный открытый уровень. На победе recordCompletion вызывается только
при выключенном чите. ResetProgress сбрасывает прогресс, а не настройку
чита; пока чит включён, все уровни остаются доступны.

Изменены SettingsStore/SettingsFormat, MenuController, LevelController,
SettingsView, LevelSelectView, Localization и контекст. Новые изображения
и правки world не понадобились. Тесты, проверочные сборки, редактор и игра
не запускались. Рабочая библиотека успешно обновлена (target
liberate_the_sheep, exit0). Человеку после Stop → Reload → Play проверить:
включить чит, открыть39-й уровень; выключить и увидеть прежние замки;
перезапустить и убедиться, что значение переключателя сохранилось.

## Уровни 10–24 и овечка с бомбой (2026-10-28)

`Game/LevelCatalog` содержит общий `kCampaignLevelCount=24`. Первые девять
конфигураций сохранены; 10-й без бомбы, на 11–24 по одной бомбе, 70…45 s.

задание и сведения: `SourceArt/Gameplay/sheep_bomb.md`.

Бомба продолжает отсчёт во время бега и уступания пути. Спасение — центр
на линии выхода x=columns/2 и y <= -kFenceOffset-1.10, чтобы весь хвост
оказался за воротами. Таймер и EscapeHerd используют один step <=0.1 s;
перед дедлайном движение ограничивается оставшимся временем. Победа
по-прежнему только после ухода всех овечек с экрана. Подсказка сначала
проходит цепочку блокеров бомбы. Перезапуск/смена уровня сбрасывает таймер,
обучение, маркеры, реакции и эффект; прочтённая карточка не повторяется
до сброса прогресса. При истечении времени обычный режим показывает
вспышку/дым 0.65 s, через 0.70 s — отдельное поражение от бомбы.
В бессмертном режиме на нуле безопасный дымок, состояние Defused,
овечка остаётся доступной, сердец и поражения нет.

## Отдельный нерешённый блокер: смешивание Sprite в PandaEditor (2026-10-01)

Новый скриншот пользователя подтверждает: RGB-padding тоже не убрал чёрную
полосу. Прежняя диагностика была неполной; НЕ считать проблему решённой и не
продолжать перерисовку/перезапуски вслепую.

Read-only разбор уже самого установленного PandaEditor (не только SDK) показал:
Renderer2D::flush задаёт 0x4 без blending; RendererMetal::submit извлекает
blending из бита 0x10. default_unlit пишет sampled RGBA без смешивания с травой,
отбрасывая лишь alpha <=0.01. Tonemap сохраняет альфу. EditorLayer передаёт
ту же итоговую native texture в ViewportView/ImageView, а UI включает 0x10:
полупрозрачная кромка смешивается с тёмным фоном панели, НЕ с травой сцены.
Это объясняет, почему RGB-padding импортируется правильно, но контур остаётся.
Загрузка RGBA на GPU прямая, дополнительного premultiply не обнаружено.

Нормальное решение — корректное alpha blending и порядок отрисовки в Sprite-pass
движка. Project-only обход: отдельный cutout-материал забора (discard малой альфы,
оставшаяся alpha=1), но это даёт более жёсткий край. Публичный Camera API не
имеет alpha override. Установленное приложение, SDK и исходники движка не менять
без разрешения пользователя; запросить направление и актуальные исходники.
В этом ходе изменена только документация; тесты/сборки/игра не запускались.

## Архитектурные правила игры

- Процедурные уровни используют общий gameplay `.world`; отдельный мир для каждого
  номера уровня не нужен (уточнение пользователя к первоначальному плану).
- Главное меню также хранить в отдельном `.world`; стартовая конфигурация готовой
  игры должна открывать именно мир меню.
- Если объект может существовать уже при старте world, создавать его в `.world`, а
  не из C++. Так геометрию, трансформы, компоненты, связи и параметры можно менять в
  PandaEditor без перекомпиляции.
- Из кода создавать только действительно динамические/временные/процедурные объекты.
- Контроллер уровня должен находить заранее созданные объекты по тегам или получать
  ссылки через опубликованные `EntityHandle`-поля.
- Переходы между меню и уровнями делать через опубликованные `WorldHandle`-поля и
  `Bamboo::WorldAPI::load()`. Идентификаторы миров задаёт редактор.
- Для меню/HUD: постоянный сценовый фон, камеры, свет и декорации живут в world;
  интерактивную интерфейсную иерархию удобно собирать через PandaUI.

## Рабочий цикл

1. Если PandaEditor открыт, перед внешней правкой попросить пользователя сохранить
   несохранённые изменения. Иначе Reload может показать конфликт disk/editor.
2. Миры и контент править в `Assets/`, C++ — в
   `Scripts/liberate_the_sheep/src/`.
3. После изменения C++ самостоятельно конфигурировать/собирать скрипты:

   ```sh
   PANDA_SDK_DIR=/Applications/PandaEditor.app/Contents/Resources/PandaSDK/lib/cmake/PandaSDK \
     Scripts/liberate_the_sheep/scripts/configure_scripts.sh debug
   PANDA_SDK_DIR=/Applications/PandaEditor.app/Contents/Resources/PandaSDK/lib/cmake/PandaSDK \
     Scripts/liberate_the_sheep/scripts/build_scripts.sh debug
   ```

   Конфигурация нужна один раз, если существует совместимый CMake cache; сборка —
   после каждой правки C++.
4. Редактор и игру запускает только пользователь. Перед загрузкой новой скриптовой
   библиотеки Play/Simulation должен быть остановлен.
5. В конце попросить пользователя нажать Reload (`Cmd/Ctrl+R`) и проверить игру.
6. После Reload редактор обновляет `.Panda/scripts-manifest.json`; только после этого
   привязывать опубликованные поля скриптов в world.

## Правила `.world`

- `.world` — JSON. Проверять синтаксис после каждой ручной правки.
- Обязательные ключи сущности: `id`, `tagComponent`, `relationshipComponent`,
  `transformComponent`, `scriptListComponent`.
- `id` — уникальный ненулевой случайный `uint32`; не переиспользовать удалённые ID.
- `rotation` в файле — quaternion `{x,y,z,w}`; identity — `{0,0,0,1}`.
- Иерархия двусторонняя: родитель содержит ребёнка в `children`, ребёнок содержит ID
  родителя в `parent`. У корня `parent: 0`; трансформ ребёнка локальный.
- Для неизвестного компонента сначала создать пример в PandaEditor, сохранить world и
  использовать полученный JSON как схему. Установленный SDK пока не содержит
  упомянутый документацией `Panda/Serialization/ComponentDtos.hpp`.
- Ссылки на entity используют ID сущности того же world. Ссылки на texture/material/
  world используют ID ассета, назначенный редактором.
- После правки проверять: валидный JSON, уникальность ID, существование parent/children,
  согласованность обеих сторон иерархии и корректность всех ссылок.

## Скрипты и поля

- Скрипт наследуется от `Bamboo::Script` и регистрируется `REGISTER_SCRIPT(Class)`.
- Доступный lifecycle: `start`, `update`, `lateUpdate`, collision/sensor begin/end,
  `shutdown`.
- Публичные inspector-поля объявляются через `PANDA_FIELDS_BEGIN`, `PANDA_FIELD`,
  `PANDA_FIELDS_END`.
- Поддержанные типы полей: `int`, `float`, `EntityHandle`, `TextureHandle`,
  `MaterialHandle`, `WorldHandle`.
- Значения по умолчанию обязательно инициализировать в C++; world может не содержать
  override для поля.
- `fieldId` никогда не вычислять вручную: брать из актуального
  `.Panda/scripts-manifest.json` после успешной сборки и Reload.
- Числовые типы в world: `0` int, `1` float, `2` entity, `3` texture,
  `4` material, `5` world.
- API мира, сущностей, компонентов, ассетов и PandaUI — main-thread-only.
  `Bamboo::Async::work` выполняет только вычисления над копиями/plain data;
  результат применяется через `complete` на main thread. Не захватывать живой `this`
  в долгую фоновую работу.
- В `shutdown()` освобождать runtime-ресурсы и очищать PandaUI root, если скрипт им владеет.

## Ассеты

- Новые файлы класть в `Assets/`; ID и метаданные создаёт редактор после сканирования.
- Не редактировать вручную служебные реестры, манифесты, cookies, cooked/cache-файлы
  внутри `.Panda/` и sidecar `.pmeta`.
- Документация/скиллы описывают `.Panda/assets.json` как реестр. В текущем пустом
  проекте этот файл ещё не создан, а у `world.world` уже есть sidecar `.pmeta`.
  Перед использованием ID смотреть фактически сгенерированные редактором метаданные;
  если ID отсутствует — просить пользователя сделать Reload/rescan, а не придумывать ID.
- Цветовые текстуры — sRGB. Для normal/roughness/noise и других data maps пользователь
  должен отключить sRGB в инспекторе.
- `.mat`: можно менять значения `inputs`, но нельзя менять набор/порядок полей контракта
  шейдера. Новый материал создавать через редактор.
- glTF хранить вместе с `.bin` и текстурами; созданные редактором материалы не дублировать
  вручную без необходимости.

- В текущем PandaSDK есть ошибка адресации atlas: `setCell()` в рендере получает
  колонку как `index % cols`, но строку тоже как остаток — `index % rows` — вместо
  обычного `index / cols`. Поэтому `MenuDiorama::pandaAtlasIndex()` преобразует
  логический row-major кадр в совместимый индекс перед вызовом `setCell()`; в
  `Runner::frame` при этом хранится именно логический кадр. Для `16×15` такое
  однозначное преобразование существует, потому что 16 и 15 взаимно просты, и оно
  проверяется `static_assert` для всех 240 ячеек. Старый gameplay-atlas `3×1` этой
  ошибкой не затронут; новый `10×3` использует аналогичное преобразование в
  `LevelController::setSheepFrame`. После исправления PandaSDK workaround следует удалить.
- Движение вынесено в независимый от Panda `MenuSheepMotion`. Прыжок проходит
  по параболе `y = H*(1-u²)`, `u=x/A`, с постоянным ускорением вниз, без плоской
  «зависшей» вершины. Высота обычной овцы — `0.90` world unit, скорость полёта —
  `1.925` world units/s, всего на `10%` выше наземной. Время не фиксируется искусственно:
  оно получается из безопасной ширины дуги и скорости, для текущего тюка — около
  `1.39 s`. Более широкое препятствие удлиняет прыжок, а не заставляет овцу резко
  ускоряться. При расчёте ширины сена используется видимая alpha-часть картинки
  (`0.425*scaleX` полуширины), а не прозрачные поля всего Sprite.
  Полуширина `A` рассчитывается по всему интервалу перекрытия силуэта и сена,
  с целевым запасом `0.10` world unit. Дополнительный запас на несуществующие
  runtime-повороты/растяжение удалён: он неоправданно удлинял дугу.
- `routeDistance(time, arc)` и обратная `routeTime(distance, arc)` связывают расписание
  с фактической позицией. Перед взлётом и после касания скорость плавно меняется за
  `0.16 s`, без скачка горизонтальной скорости на границах. Подготовка, полёт и
  восстановление проигрывают jump-позы `0…4`, `4…20`, `20…23` соответственно.
  Первая и последняя jump-позы совпадают с run-позой `0`.
  Центр Sprite в покое остаётся на `0.26*scaleY` выше травы; runtime добавляет только
  параболический подъём, а позы животного берутся из сохранённых цельных рисунков.
- Регрессионная проверка `MenuSheepMotionSmoke` проверяет весь пролёт, включая оба
  направления и разные масштабы: полный силуэт не должен пересекать тюк.
  Проверяются последовательность jump-поз, отсутствие скачков трансформа и скорости,
  монотонность/обратимость маршрута, постоянное ускорение в воздухе, высота и
  длительность обычного прыжка, ограничение скорости полёта и связь 48 фаз бега
  с расстоянием. Отдельная проверка запрещает дополнительные runtime-покачивания

  исходными картинками, без перекомпоновки конечностей. Поле движения общее для
  трёх окрасов, чтобы они сохраняли одинаковые силуэты и точки привязки.

## Проверенные ограничения текущего SDK

- ABI скриптов: версия 23.
- В `Input.hpp` объявлены `getMousePositionX/Y()` и `getMouseScrollX/Y()`, но в
  поставленной `libPandaSDK.a` для них нет символов. Пока не использовать: будет ошибка
  линковки. `getMouseDeltaX/Y()`, клавиши, кнопки мыши и touch доступны.
- Установленный пакет содержит библиотеки только для macOS/Metal; экспорт на другие
  платформы потребует соответствующего PandaSDK.
